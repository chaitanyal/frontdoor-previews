# Practice link previews

Use clinic-facing `seo.title`, `seo.description`, `seo.ogImage` and
`seo.ogImageAlt` in practice.json for both previews and standalone production.
Keep concept/sales wording out of these fields so production requires no metadata
cleanup. Preview indexing remains separately controlled by `seo.allowIndexing`.

Share images should identify the practice, explain its care focus, show its location
and give a contact number. A landscape alone does not communicate those details.
Use a static PNG so messaging clients can display the card without running scripts.

Generate a 1200 × 630 clinic-facing card using existing practice content and hero imagery:

```sh
node scripts/generate_share_images.mjs northhillspsychiatry northwestpsychiatry mariposa
```

Each output is `sites/<slug>/images/social/practice-share.png`. Set `seo.ogImage`
to `./images/social/practice-share.png` and describe the card in `seo.ogImageAlt`.
The generator reads practice name, location, tagline, hero title/image and phone
directly from practice.json. It does not generate new healthcare claims or change
configuration. Regenerate after changing any of those fields. Build normally to
copy the asset into published output. This rendering command is asset creation,
not verification.

Centex retains its selected branded variant at
`sites/centexmh/images/social/centexmh-production-share.png`, generated by its
[retained composition script](../assessments/centexmh/sources/social-preview/generate-production.mjs).
The generic generator is available for future practices without a bespoke design.

Messaging clients can cache cards for previously shared URLs. A deployment updates
the metadata/image but cannot force old cards in existing conversations to refresh.
